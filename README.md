# SMT / Quasimodo система для MetaTrader 5 (металлы и форекс)

Два скрипта на одном ядре: **`main.py`** (realtime-торговля через терминал MT5) и
**`backtest.py`** (бэктест на истории MT5 или CSV, работает на любой ОС).

## Торговая логика

1. **Структура на main TF** — фрактальные свинги с разметкой HH/HL (аптренд) и LL/LH
   (даунтренд). Тренд определяется по слому структуры закрытием (BOS/CHoCH).
2. **Два пула внешней ликвидности.** В аптренде: последний свинг-минимум и максимум,
   сформированный после него; в даунтренде — зеркально.
3. **Свип пула — строго 2 свечи:**
   * свеча-прокол: хвост выходит за уровень, но закрытие остаётся по «нужную» сторону
     (никакого закрепа телом за уровнем);
   * свеча-реакция: тело в сторону сделки с закрытием от уровня.
   Если ещё до свипа была свеча с закрытием за уровнем — пул считается пробитым,
   свип не засчитывается. **Свип минимума → лонг, свип максимума → шорт.**
4. **SMT-дивергенция** по снятию ликвидности с коррелятом:
   * `XAUUSD ↔ XAGUSD` — прямые корреляты;
   * `EURUSD ↔ iDXY` — индекс доллара, инвертированный программно (high↔-low и т.д.).
   Дивергенция = наш инструмент экстремум снял, коррелят соответствующий экстремум
   удержал. По умолчанию режим `require_if_available`: SMT обязательна, но если у
   брокера нет коррелята (например, нет DXY) — сделка допускается без неё.
   **Quasimodo**-конфлюэнс (хвост свипа в зоне QML–head паттерна) может заменять SMT
   (`qm_substitutes_smt = True`).
5. **Подтверждение входа — inversion FVG на LTF** (модели `15m+5m`, `1h+5m`, `5m+3m`):
   для покупки берётся медвежий FVG, инверсия = **полное закрепление телом** —
   закрытие ВЫШЕ верхней границы гэпа (по SMC); для продажи зеркально.
   Подтверждение ищется в окне `confirm_window_main` main-баров после свипа.
6. **Риск-менеджмент:** SL за экстремумом свипа (+буфер от ATR), TP — противоположный
   пул ликвидности; если до пула RR < `min_rr`, цель ставится по `rr_fallback` R.
   Объём — от доли эквити (`risk_per_trade`), опциональный перенос в безубыток.

## Ограничения торговли

* **Торговая сессия — 02:00–10:00 по Нью-Йорку** (`session_start` / `session_end` /
  `session_tz` в `config.py`, DST учитывается автоматически). Входы разрешены только
  внутри окна; в realtime время берётся по системным часам, в бэктесте — по времени
  баров, приведённому к UTC через `bars_utc_offset_hours` (смещение сервера брокера,
  обычно 2 или 3; для истории из MT5 укажите `--bars-utc-offset`).
* **Дневной лимит убытка — 3% от эквити на начало дня** (`max_daily_loss_pct`,
  0 = выключено). День считается по `session_tz`. После срабатывания новые входы
  блокируются до следующего дня; `daily_loss_close_positions = True` дополнительно
  закрывает открытые позиции системы.

## Переключатели стратегий (`config.py` или CLI)

| Переключатель | Config | CLI | Эффект |
|---|---|---|---|
| SMT вкл/выкл | `use_smt` | `--no-smt` | без дивергенций, торгуем свипы |
| Quasimodo вкл/выкл | `use_quasimodo` | `--no-qm` | QM не учитывается и не заменяет SMT |
| Только с Quasimodo | `require_qm` | `--require-qm` | входы только при QM-конфлюэнсе |
| iFVG-подтверждение | `require_ifvg` | `--sweep-only` | вход сразу по свипу, без LTF |
| Только по тренду | `with_trend_only` | `--with-trend-only` | контртрендовые свипы игнорируются |
| ТФ-модели | `enabled` в `TF_MODELS` | `--models M15/M5 ...` | выбор моделей |
| Сессия | `session_enabled` | `--no-session` | снять ограничение по времени |
| Дневной лимит | `max_daily_loss_pct` | `--max-daily-loss 0.03` | 0 = выключить |

Примеры комбинаций: «только свипы, без всего» — `--sweep-only --no-smt --no-qm`;
«классика со строгой SMT только по тренду» — `--smt-mode require --with-trend-only`;
«только сильнейшие сетапы» — `--require-qm --with-trend-only`.

## Структура проекта

```
smt_mt5_system/

├── backtest.py             # бэктест (MT5-история или CSV, любая ОС)

│   ├── patterns.py         # двухсвечной свип, FVG/iFVG, SMT, инверсия серии (iDXY)

│   ├── session.py          # торговая сессия NY и границы дня (DST)
```

## Установка

```bash
pip install -r requirements.txt
```
Для realtime нужен **Windows + установленный терминал MT5** с включённой
алготорговлей (пакет `MetaTrader5` ставится только на Windows). Бэктест по CSV
работает на любой ОС.

## Realtime

```bash
# терминал уже запущен и залогинен:
python main.py --symbols XAUUSD EURUSD --dry-run        # сначала только сигналы!
python main.py --symbols XAUUSD EURUSD --risk 0.005     # боевой режим, риск 0.5%

# логин прямо из скрипта / выбор терминала:
python main.py --login 123456 --password *** --server Broker-Demo --path "C:\...\terminal64.exe"
```
Полезные флаги: `--no-smt`, `--no-qm`, `--sweep-only`, `--models M15/M5 H1/M5`,
`--smt-mode prefer|require|require_if_available`, `--with-trend-only`,
`--no-session`, `--session-start 02:00 --session-end 10:00`,
`--max-daily-loss 0.03`, `--breakeven-r 1.0`, `--dry-run`.
Все сигналы и действия пишутся в `smt_system.log`; сработавший дневной лимит
и блокировка входов отражаются в логе явно.

## Бэктест

```bash
# история из терминала MT5 (Windows), все три ТФ-модели:
python backtest.py --symbol XAUUSD --source mt5 --start 2026-02-01 --end 2026-08-01 --model all --plot

# CSV (любая ОС); коррелят по желанию (без него SMT в require_if_available не блокирует):
python backtest.py --symbol EURUSD --source csv \
    --csv-main eur_m15.csv --csv-ltf eur_m5.csv --csv-corr dxy_m15.csv \
    --tf-main M15 --tf-ltf M5 --plot
```
CSV принимается и «обычный» (`time,open,high,low,close`), и экспорт MT5
(`<DATE> <TIME> <OPEN> ...`). Для `EURUSD` коррелят из `--csv-corr`
инвертируется автоматически (iDXY) по карте `SMT_MAP`.

Результаты в `bt_results/`: `trades_*.csv` (все сделки), `stats_*.json`
(winrate, total R, profit factor, просадка, разбивки по моделям / направлению /
SMT / QM / типу выхода), `equity_*.png`.

Проверка на встроенной синтетике:
```bash
python tests/make_synth.py
python backtest.py --symbol XAUUSD --source csv --csv-main tests/data/main_m15.csv \
    --csv-ltf tests/data/main_m5.csv --csv-corr tests/data/corr_m15.csv --plot
python tests/test_core.py
```

## Ключевые настройки (`config.py`)

| `session_start`–`session_end` | 02:00–10:00 | торговое окно по `session_tz` (NY) |
| `bars_utc_offset_hours` | 0 | смещение времени баров от UTC (бэктест) |

| `daily_loss_close_positions` | `False` | закрывать позиции при срабатывании |
| `SMT_MAP` | XAU↔XAG, EUR↔iDXY | корреляты и флаг инверсии |
| `smt_mode` | `require_if_available` | политика SMT-фильтра |
| `qm_substitutes_smt` | `True` | Quasimodo может заменить SMT |
| `max_sweep_age` | 3 | свежесть свипа (main-баров) |
| `confirm_window_main` | 8 | окно ожидания iFVG (main-баров) |
| `min_rr` / `rr_fallback` | 2.0 / 2.5 | мин. RR до пула / RR-цель |
| `sl_buffer_atr` | 0.1 | буфер SL (доля ATR main) |
| `risk_per_trade` | 0.005 | риск на сделку (0.5% эквити) |
| `with_trend_only` | `False` | торговать только по тренду |
| `breakeven_at_r` | 0.0 | перенос SL в БУ при +N R |

## Важно перед боевым запуском

* Уточните у брокера **тикер индекса доллара** (DXY/USDX/…) и наличие **M3** —
  алиасы подбираются автоматически, но не у всех брокеров эти данные есть.
  Если M3 нет, замените модель в `TF_MODELS` (например, на `M5+M1`).
* Прогоните `backtest.py --source mt5` на **реальной истории вашего брокера**
  и подберите `min_rr`, `smt_mode`, `with_trend_only` под инструмент.
* Начинайте с `--dry-run` и малым риском; в одном инструменте система держит
  не более одной позиции (magic `557001`).
* Бэктест не моделирует проскальзывание и точные тики внутри бара
  (консервативно: SL и TP в одном баре = SL). Результаты на синтетике — только
  проверка механики, а не оценка доходности.

## Запуск на постоянку (VPS) и проп-режим

**Инфраструктура.** Windows VPS (терминал и пакет MetaTrader5 работают только на Windows),
работающий 24/5. В терминале: выполнен вход в счёт, включена «Алготорговля»
(Сервис → Настройки → Советники → разрешить). Терминал должен быть просто запущен —
скрипт подключается к нему по IPC.

**Автозапуск.** В корне проекта лежит `run_live.bat` — он запускает `main.py` и
перезапускает его при любом падении. Сам скрипт при старте ждёт терминал (повтор
каждые 30 с) и автоматически переподключается, если связь с терминалом пропала
(~1 мин без данных). Настройка автостарта: Планировщик заданий Windows → два задания
«При входе в систему»: 1) `terminal64.exe`, 2) `run_live.bat` (с задержкой 1–2 мин);
плюс автологин Windows на VPS. Контроль — файл `smt_system.log` (и `restart.log`
от батника).

**Проп-режим (пример: дневной лимит 5%, общий 10%, цель 8%).** Внутренние лимиты
системы ставятся С ЗАПАСОМ под лимиты пропа, потому что лимит пропа считается по
эквити (включая плавающий минус) и нарушение = потеря счёта:

| Лимит пропа | Настройка системы | Запас |
|---|---|---|
| Дневной −5% | `--max-daily-loss 0.03 --close-on-limit` | ~2% |
| Общий −10% | `--max-total-loss 0.08 --initial-balance <старт. баланс>` | ~2% |

`--initial-balance` задавайте явно (стартовый баланс проп-счёта): тогда общий стоп
не «съезжает» при перезапусках скрипта. При срабатывании общего стопа торговля
останавливается насовсем (до ручного перезапуска), позиции закрываются.
Торговая сессия 02:00–10:00 Нью-Йорка целиком лежит внутри одного CE(S)T-дня,
по которому большинство пропов считает дневной лимит, — рассинхрона «дней» нет.
Перед стартом проверьте правила пропа: перенос позиций через ночь/выходные и
торговля в новости (система может держать позицию несколько дней).
